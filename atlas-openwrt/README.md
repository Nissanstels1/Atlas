## Возможности

- До 64 HTTPS подписок, до 512 узлов в каждой, до 4096 профилей суммарно; runtime-пул настраивается до 1024 узлов. Ответ подписки ограничен 4 МиБ.
- Локальный импорт URI/Base64/Clash/Mihomo YAML/sing-box JSON прямо из текста (до 256 КиБ). Движок проверяет профили до сохранения; локальные источники можно включать и выключать без сетевого обновления.
- Пакетный импорт до 64 ссылок за раз, проверка HTTPS/Happ URL и отчёт о добавленных ссылках, дубликатах и ошибках.
- Импорт Happ `happ://crypt5/`: ссылка и зашифрованное тело подписки расшифровываются локально; требуется `python3-cryptography`.
- FakeIP для проксируемых доменов либо всей DNS-зоны в глобальном режиме; TTL FakeIP настраивается (по умолчанию 60 секунд).
- Фильтр рекламы/трекеров через AdGuard DoH; до 16 удалённых списков domains, hosts, CIDR, AdGuard, sing-box JSON или SRS. До 10 000 правил на список и 50 000 суммарно; последний хороший кеш сохраняется при сбое обновления. Списки можно обновлять через общий или отдельный пул подписки без прямого fallback.
- Экран конфиденциальности: проверка настроек DNS/TLS/ECS/FakeIP, DHCP/dnsmasq, живой DNS-запрос на роутере, функциональный self-test, а также сравнение внешнего IP напрямую и через выбранный узел.
- URI, Base64 URI, Clash/Mihomo YAML и sing-box JSON subscriptions; YAML разбирается безопасным ограниченным loader без alias и повторных ключей. JSON outbounds проходят фильтр полей и финальную проверку sing-box.
- VLESS/Reality/Vision, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, AnyTLS, SOCKS4/4a/5 и HTTP CONNECT; TCP, WebSocket, gRPC gun, HTTP/H2 там, где их поддерживает протокол.
- Provider HTTP-заголовки для авторизованных источников хранятся в state-файле роутера и не возвращаются в LuCI status; перенаправления на другой origin запрещены. Заголовки можно заменить или удалить.
- ETag и Last-Modified позволяют запрашивать неизменённые подписки условно; после обновления показывается число новых и удалённых профилей. Ошибка сохраняет последний рабочий список.
- Ручной выбор либо авто: минимум/максимум/стабильность пинга, диапазон пинга, порядок предпочтительных стран и жёсткие исключения стран. sing-box измеряет узлы, Atlas раз в минуту выбирает по актуальным замерам; простой режим использует штатный URLTest.
- Проверка страны IP выхода отдельного профиля через ipapi.co; сохраняются только код страны и время, результат действует 30 дней. Можно требовать проверенную страну для фильтров. При пустом пуле из-за новой геопроверки или истечения доказательства Atlas останавливает туннель, включает fail-closed и отключает автоматический рестарт старого выхода.
- Практический self-test FakeIP: новый DNS A запрос к локальному dnsmasq должен вернуть только адреса из 198.18.0.0/15.
- Проверка каждого допущенного фильтрами сервера настоящим HTTPS запросом через временный локальный прокси.
- Обновление подписок раз в 1–168 часов; минутный планировщик проверяет срок, выбирает профиль и проверяет службу.
- Лимит, использованный трафик и срок подписки из `subscription-userinfo`, если их сообщает провайдер.
- Режим «по правилам» или «весь трафик», доменные суффиксы, IPv4/IPv6 CIDR, приоритетные исключения.
- Секции маршрутизации proxy/direct/exclude/block/interface с доменами, CIDR, IP-источниками и входными интерфейсами; каждая proxy-секция может использовать отдельный авто-пул, DNS-секции — свой DoH/DoT/UDP resolver по тому же маршруту. Маршрутизация/исключение целых LAN-устройств, блок QUIC (UDP/443), исключение NTP (UDP/123).
- Fail-closed режим через fw4 блокирует LAN→WAN fallback, если трафик выходит мимо Atlas TUN; сам роутер и локальная сеть доступны.
- Импорт локальных UTF-8 `.txt`, `.lst`, `.json` списков (до 64 КиБ) с действием proxy/direct/block; списки проверяются на роутере.
- LAN listener HTTP/SOCKS с выбором частного адреса и обязательной аутентификацией.
- Перезагрузка реального IP для маршрутизируемых доменов через выбранный защищённый resolver; автоматический или закреплённый выходной сетевой интерфейс; настраиваемый уровень журналирования.
- TUN, nftables auto_redirect, отдельный экземпляр sing-box под procd.
- Проверка `sing-box check` до изменения активной конфигурации; откат при ошибке запуска. Сохранение FakeIP и выбора узлов в приватном cache file.
- Мониторинг выбранных логических интерфейсов OpenWrt (`wan`, `wan6`): событие netifd `ifup` перезапускает sing-box после восстановления интерфейса.
- По желанию управляет UCI dnsmasq `server/noresolv/cachesize`, направляя DNS клиентов в loopback inbound sing-box; хранит и восстанавливает предыдущие значения при остановке. На экране монитора показывает до 50 активных соединений, сработавшие правила, память и счётчики; API остаётся на loopback и доступен только администраторам LuCI.
- Отдельные настройки хранения runtime-конфигурации в RAM и кеша FakeIP в RAM, flash либо на действительно смонтированном USB-томе.
- Последняя успешно запущенная конфигурация хранится отдельно и используется после перезагрузки. Watchdog проверяет процесс и конфигурацию, восстанавливает последнюю рабочую конфигурацию и ограничивает автоматический перезапуск тремя попытками за 10 минут. Экран самопроверки отдельно проверяет движок, API, TUN, DNS и HTTPS через выбранный узел.
- URL, UUID и пароли не возвращаются методом статуса. Секретные файлы имеют права 0600, каталог 0700. У rpcd отдельные права чтения/записи; произвольный shell через API недоступен.

## Совместимость и ограничения

Целевая платформа — **OpenWrt 24.10+ с fw4**, sing-box **1.12+**. Стенд проверки версии 0.14.0 — OpenWrt 24.10.7 x86/64 QEMU с sing-box 1.12.22. Результаты штатного RPC, импорта, TUN, монитора и DNS/FakeIP находятся в `docs/verification.md`. Провайдерская подписка и реальный exit не подтверждены. См. `docs/verification.md`. Физический роутер и другие архитектуры не проверены. Приложение не содержит машинного кода; архитектуру движка выбирает пакетный менеджер. Пакет `.ipk` предназначен для OpenWrt с `opkg`; **не устанавливайте его через `apk`**.

Предоставленная Happ crypt5 ссылка была расшифрована локально в OpenWrt и принята при сохранении. Проверка загрузки вернула сетевую/TLS ошибку до разбора ответа, поэтому число профилей равно нулю и подключение серверов не подтверждено. Формат Happ и таблицы совместимости могут меняться; неизвестный ключ или неверная AES-GCM подпись останавливают импорт, не заменяя сохранённые профили. Подробнее — `docs/happ.md`.

FakeIP включается отдельно. В режиме правил он назначается только доменам в списке «Через туннель», в глобальном режиме — всем DNS-запросам. DNS AdGuard фильтрует по правилам внешнего провайдера; собственный список в Atlas также действует на уровне DNS и не блокирует рекламу, встроенную в контент. Клиентский DoH/ECH может обходить DNS-правила. Экран приватности проверяет конфигурацию Atlas; внешнее сравнение IP по явному нажатию посылает запросы к `api.ipify.org` напрямую и через выбранный узел. Atlas сохраняет только результат сравнения, но тест не способен доказать отсутствие утечек со всех клиентских устройств и не делает пользователя анонимным.

Backend использует Python 3 и стандартную библиотеку. Это упрощает проверяемость парсеров, но занимает больше flash/RAM, чем ucode. Маленький flash на 8/16 МиБ, вероятно, потребует extroot. До установки оцените свободное место командой `df -h /overlay`, размер зависимостей и память командой `free`. На тестовом x86/64 образе приложение с недостающими зависимостями заняло около 64 МиБ сверх базовой системы. Расход памяти под нагрузкой и скорость не измерены.

PyYAML 6.0.3 для Clash/Mihomo включён как чистый Python-код с MIT лицензией, без внешнего OpenWrt пакета; загрузчик ограничивает глубину/размер структуры и запрещает YAML aliases.

Не поддерживаются XHTTP/REALITY с неизвестными параметрами, VLESS encryption, плагины Shadowsocks и WireGuard endpoint-подписки. Clash proxy-groups пересоздаются настройками Atlas, а динамические `proxy-providers` не загружаются автоматически — добавляйте их HTTPS источники отдельно. Правило `interface` использует уже созданный интерфейс и не поднимает WireGuard/OpenVPN. В sing-box JSON запрещены детуры, произвольные интерфейсы/маршруты, файловые пути ключей и сертификатов, а также отключение проверки TLS. Весь удалённый конфиг никогда не исполняется.

Проверьте, что виртуальные сети `172.31.255.0/30` и `fdfe:dcba:9876::/126` не заняты. Движок должен быть собран с поддержкой нужных протоколов и uTLS для Reality.

## Установка на OpenWrt с opkg

1. Сохраните резервную копию роутера через LuCI → Система → Резервная копия. Сохраните настройки существующего прокси-клиента.
2. Передайте `dist/luci-app-atlas_0.14.0-1_all.ipk` на роутер, например в `/tmp/`.
3. Выполните по SSH:

```sh
opkg update
opkg install /tmp/luci-app-atlas_0.14.0-1_all.ipk
sing-box version
```

Если репозиторий вашей прошивки содержит sing-box старее 1.12, сначала обновите движок/прошивку из совместимого доверенного источника. Не подменяйте пакеты ядра пакетами от другой сборки OpenWrt. Если зависимости ядра отсутствуют, используйте образ с подходящими модулями.

Собранный в архиве `.ipk` — пакет приложения, не образ прошивки. Пакет успешно установлен штатным opkg в виртуальную машину OpenWrt; установка на физический роутер не выполнялась. Для воспроизводимой сборки тем же инструментарием, что у вашей прошивки, используйте OpenWrt SDK ниже.

Чтобы проверить этот выпуск в полноценном OpenWrt с интернетом на обычном Linux ПК, см. [инструкцию QEMU NAT](docs/online-test.md). Она использует отдельную виртуальную WAN сеть и loopback-доступ к LuCI.

## Установка на OpenWrt с apk либо из исходников

Распакуйте весь каталог `atlas-openwrt` на роутер, например в `/tmp/atlas-openwrt`. Установщик сам выберет `apk` или `opkg` для зависимостей, проверит Python и версию движка, затем установит файлы приложения:

```sh
cd /tmp/atlas-openwrt
sh tools/install.sh
```

Это отдельная установка файлов: само приложение не регистрируется в базе `apk/opkg`, зависимости регистрируются. Для удаления сохраните `tools/uninstall.sh`. Этот установщик не перезаписывает существующую установку Atlas. Для управляемых обновлений используйте SDK и родной пакетный формат вашей прошивки.

Пакеты: `luci-base rpcd python3-light python3-urllib python3-openssl python3-uuid python3-codecs python3-cryptography ca-bundle sing-box kmod-tun kmod-nft-tproxy kmod-nft-socket kmod-nft-queue firewall4 ip-full`. Ядро должно поддерживать TUN и nftables; для новых версий sing-box может понадобиться NFQUEUE. Используйте пакеты из репозитория именно вашей прошивки.

## Первый запуск

1. В LuCI откройте **Службы → Atlas** (Services → Atlas). Если пункта нет, обновите страницу с очисткой кеша и заново войдите в LuCI.
2. **Подписки → + Подписка:** задайте название и вставьте HTTPS ссылку либо `happ://crypt5/...`. Happ расшифровывается на роутере; пользовательская ссылка не встроена в исходники или пакет.
3. Нажмите **Обновить**. При ошибке приложение сохраняет прежние рабочие узлы; сообщение появится в карточке.
4. В **Серверы** нажмите **Проверить серверы**. Результат — длительность HTTPS подключения и ответа, а не ICMP ping. Проверки последовательные; большой список может занять несколько минут.
5. В **Настроить автовыбор** задайте реальные фильтры и включите **Авто**, либо вручную выберите допущенный сервер. В **Маршрутизация** добавьте нужные домены/IP либо выберите «Весь трафик».
6. Отключите конфликтующий клиент, например Podkop, Passwall или OpenClash. Atlas не останавливает их сам и откажется запускаться при обнаружении работающего сервиса. Проверка по имени сервиса не обнаруживает неизвестные ручные экземпляры прокси.
7. **Обзор → Запустить Atlas.** Это включает автозапуск. Изменения подписок, выбора узла и правил требуют **Применить изменения**. Успешное автоматическое обновление подписки применяет конфигурацию, если Atlas работает.

По умолчанию режим «по правилам» и пустые списки: обычный трафик идёт напрямую. DNS, который попадает в TUN, обрабатывается sing-box и отправляется к Cloudflare DoH через выбранный прокси; можно выбрать AdGuard DoH или свой DoH/DoT/UDP сервер. Bootstrap DNS для адресов узлов идёт напрямую к настроенному DoH или DoT resolver по IP (по умолчанию Cloudflare DoH на `1.1.1.1`): локальная сеть не видит DNS имена в открытом виде, но Cloudflare видит bootstrap запросы.

Приоритет: распознавание протокола → перехват DNS → локальные IP напрямую → доменные/IP исключения → доменные/IP правила туннеля → маршрут режима. Atlas не меняет UCI network/firewall; опциональный переключатель dnsmasq меняет только `server`, `noresolv` и `cachesize`, сохраняет их исходные значения и восстанавливает их при остановке. Включайте его после резервного копирования конфигурации и проверьте DNS с LAN-клиента.

Доменные правила зависят от DNS reverse mapping и распознавания TLS/HTTP/QUIC. Клиентский DoH, ECH, кеш DNS и подключения непосредственно к IP могут не дать доменное имя; используйте IP правила либо весь трафик. В настройках можно включить fail-closed firewall4: он блокирует пересылку LAN→WAN, если трафик выпадает из TUN. Локальная сеть и исходящие соединения самого роутера остаются доступными.

## Сравнение с Podkop и проверка приватности

Atlas 0.14.0 включает каталог из 24 community SRS списков, фильтры sing-box JSON, независимые подписочные пулы, `Exclusion` секции, VPN DNS resolver, FakeIP, LAN HTTP/SOCKS proxy, монитор соединений и настраиваемую интеграцию dnsmasq. Для подписок добавлены Clash/Mihomo YAML, AnyTLS, batch import, приватные HTTP-заголовки и ETag. Обновления списков можно направить через общий либо отдельный подписочный пул. Self-test проверяет DNS-запрос с роутера и HTTPS через выбранный узел. Интеграция dnsmasq выключена по умолчанию; fail-closed kill switch также выключен по умолчанию. См. [матрицу функций](docs/podkop-comparison.md). Экран не проверяет WebRTC или браузерный fingerprint и не подтверждает анонимность.

## Фильтры, Эстония и автоматическое переключение

**Серверы → Настроить автовыбор → Только Эстония** задаёт фильтр `EE` и автоматический режим. На работающем Atlas кнопка сохраняет и применяет конфигурацию; если сервис остановлен — сохраняет до запуска.

Фильтры стран, протоколов и названий ограничивают реальные outbounds движка. Несколько значений одного фильтра объединяются через ИЛИ; разные фильтры — через И. Исключение по названию имеет приоритет. Поиск над таблицей влияет только на отображение. Фильтры по названию — буквальное совпадение без учёта регистра, не regex.

Без геопроверки страна определяется по флагу или начальному коду в названии: `🇪🇪`, `[EE]`, `EE `. Это только метка провайдера. Кнопка «Проверить IP выхода» делает HTTPS запрос через этот профиль к ipapi.co/country/; свежий результат имеет приоритет над меткой. Опция «только проверенный IP» исключает неподтверждённые или старые страны при заданных страновых фильтрах. Если после проверки допустимый пул пуст, fail-closed остаётся включённым до изменения настроек; после выбора допустимого пула Atlas нужно запустить вручную.

Для проверки вашей Happ-подписки сервер пока не вернул список профилей из-за запрета исходящего HTTPS в тестовой среде. Поэтому страну и наличие серверов в Эстонии по этой подписке не удалось подтвердить. Для загруженных подписок можно задать `EE` как обязательную страну либо настроить приоритет `EE, DE, NL`; страна извлекается из имени профиля и не подтверждает геолокацию выхода.

Atlas может предпочитать страны по порядку, выбирать минимальный, максимальный либо наиболее стабильный измеренный HTTPS RTT и исключать узлы за заданными порогами. Для пользовательских критериев Atlas использует только свежие замеры sing-box и оставляет текущий узел, если свежих подходящих замеров нет. Обычный fastest режим остаётся штатным URLTest. Переключение не мгновенное: зависит от интервала и таймаута. После 30 минут без трафика периодические проверки приостанавливаются до нового трафика. Если все подходящие узлы недоступны, рабочее соединение не гарантируется; фильтр сам не расширяется и другой стране разрешение не выдаётся.

По умолчанию существующие соединения не разрываются при смене узла; новые используют текущий выбор. Опция **Разрывать текущие соединения** помогает принудительной смене, но может прервать звонки и загрузки.

Карточка **Фактически выбран движком** читает цепочку selector → URLTest у запущенного sing-box. Она не выводит предположение из сохранённых настроек или результатов отдельного пробника. API слушает только `127.0.0.1:19090`, защищён случайным 256-битным секретом. Секрет не передаётся в LuCI. Нужна сборка sing-box с Clash API; занятый порт вызывает ошибку запуска и откат. После обновления с 0.1 примените настройки для включения этого API.

Факт выбора не является доказательством успешного соединения. В OpenWrt VM подтверждён переход на резервный локальный VLESS сервер после остановки основного; HTTPS через резервный вернул 204. Серверы из реальной подписки этим тестом не проверяются.

## Диагностика и восстановление

```sh
ubus call atlas status '{}'
/etc/init.d/atlas status
logread -e sing-box
logread -e atlas
```

`status` скрывает секреты. Системные журналы движка могут содержать адреса назначений; учитывайте это, если будете публиковать их.

Отключение и восстановление прямого доступа:

```sh
/etc/init.d/atlas disable
/etc/init.d/atlas stop
```

При ошибке новой конфигурации предыдущая сохраняется. Проверка успешного запуска подтверждает процесс, **не доступ в интернет**. Если формат валиден, но узел недоступен, требуется выбор другого сервера; автоматический откат по качеству соединения не реализован.

Данные: `/etc/atlas/controller.json` (секрет локального API), `/etc/atlas/state.json` (подписки, URL, узлы и настройки), `/etc/atlas/active.json` (последняя успешно запущенная конфигурация). Эти файлы содержат ключи доступа. Перед sysupgrade отдельно сохраните `/etc/atlas/` и включите каталог в резервную копию. Состояния фоновых задач и результаты проверок находятся в `/var/run/atlas/` и сбрасываются после перезагрузки.

Удаление пакетной установки:

```sh
opkg remove luci-app-atlas
```

Для APK, собранного SDK: `apk del luci-app-atlas`. Для отдельного установщика: `sh tools/uninstall.sh`. Каталог `/etc/atlas/` и общие зависимости намеренно сохраняются.

## Сборка в OpenWrt SDK

Для готовых `.ipk`, source ZIP и `SHA256SUMS` выполните `python3 tools/build_release.py`.

Скопируйте этот каталог в `package/luci-app-atlas` SDK вашей целевой версии:

```sh
./scripts/feeds update -a
./scripts/feeds install -a
make menuconfig
# LuCI → Applications → luci-app-atlas
make package/luci-app-atlas/compile V=s
```

SDK формирует родной пакет своей версии, включая APK при соответствующем target. Сборка в SDK в этой среде не запускалась. Скрипт `python3 tools/build_ipk.py` пересобирает независимый от архитектуры `.ipk` для opkg; контрольная сумма находится в `dist/SHA256SUMS`.

### Новое в 0.14

Сохранение FakeIP при строгом автовыборе без восстановления старого выбора узла. Опциональная проверка FakeIP из браузера и сравнение маршрутов через внешние диагностические сервисы. Это не гарантия анонимности и не доказательство превосходства по производительности.
