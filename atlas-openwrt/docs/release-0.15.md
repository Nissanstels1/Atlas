# Atlas 0.15.0 beta

## Изменения

- Секции маршрутизации: точные порты, диапазоны портов, TCP/UDP. Можно комбинировать с доменами, IP назначения, устройствами и входящими интерфейсами. Портовые альтернативы объединяются через ИЛИ; разные условия секции через И.
- Совместимость с прежними секциями из 8/9 полей; новые поля 10/11 необязательны. Сохранённые настройки получают пустые новые списки.
- Исправлена обработка запятых в секциях и удалённых списках LuCI: запятая внутри поля больше не разделяет запись на несколько строк.
- Проверка серверов: максимум два одновременно при доступной памяти от 256 МиБ, иначе один. При отсутствии concurrent.futures остаётся последовательный режим без новой обязательной зависимости.
- Очередь не создаёт тысячи ожидающих заданий. Только основной поток пишет результаты и состояние операции; результаты сохраняются сразу после завершения узла.
- Ошибка одного диагностического процесса не прерывает оставшиеся узлы. Исключения не публикуют чувствительные параметры; итог показывает число ошибок.
- Проверки серверов и внешнего IP больше не открывают и не блокируют кеш основного sing-box.

## Проверки этой версии

- 9 тестов новых правил, кеша и планировщика проверок.
- 6 тестов структуры IPK, приватных прав настроек и установочных сценариев.
- 2 теста исходного архива и контрольных сумм.
- DOM-тест LuCI: прежние сценарии и сохранение новой секции с портами/диапазонами/UDP.
- Три конфигурации портовых правил приняты sing-box 1.12.17 и 1.14.2 на Windows. Для проверки использован loopback mixed inbound вместо Linux TUN: это проверка конфигурации, а не реального перехвата пакетов.

Исторические результаты в остальных документах относятся к старым версиям. Полный Linux-набор backend-тестов здесь не выполнен: backend использует fcntl, среда Windows; WSL недоступен. Mock-проверки не заменяют запуск OpenWrt.

## Границы

Целевой диапазон — OpenWrt 24.10.1 и новее. IPK предназначен для систем с opkg; устанавливать его через APK нельзя. Нативный SDK-builder сохранён; готовый APK не собран. На OpenWrt 24.10.1 эта версия ещё не установлена. Для веток с другой версией sing-box нужны отдельные проверки конфигурации.

DNS resolver не допускается вместе с портами/транспортом, поскольку DNS не содержит порт назначения последующего соединения. Такие секции не добавляют DNS/FakeIP правила. Для FakeIP создайте отдельную доменную секцию.

Два одновременных теста могут изменить измеренные задержки из-за конкуренции за канал. Скорость проверки и расход памяти на конкретном роутере пока не измерены. Пользовательские критерии автоселектора используют замеры своего рабочего движка, а не эти диагностические проверки.

## Что требуется для утверждения «лучше Podkop по всем параметрам»

1. Установка и обновление Atlas и актуального Podkop на одинаковых OpenWrt 24.10.1, актуальной 24.10 и новой стабильной ветке; x86/64, ARM и MIPS.
2. Замеры RAM, CPU, времени запуска, скорости TCP/UDP и задержек под нагрузкой; одинаковые серверы и списки правил.
3. Проверка пути LAN-клиента: IPv4/IPv6, DNS/FakeIP, QUIC, клиентский DoH, WebRTC, fail-closed, остановка движка и обрыв WAN.
4. Проверка procd respawn, обновлений подписок и списков, пустых пулов, отказов DNS, заполнения диска, восстановления настроек и sysupgrade.
5. Сборка и установка APK официальным SDK; проверка совместимости с движком новой ветки.
6. Решение оставшихся продуктовых пробелов: полноценный визуальный редактор секций вместо строк с разделителями, безопасное редактирование дополнительных outbound-параметров, проверяемый импорт настроек и диагностический отчёт.

До этих проверок выпуск остаётся beta; превосходство по всем параметрам не подтверждено.
