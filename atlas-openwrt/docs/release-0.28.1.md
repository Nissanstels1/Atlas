# Atlas 0.28.1 — контроль ресурсов и ARM64

В мониторе соединений появились размер базы кэша, свободное место на её разделе и доступная память всей системы. При размере кэша от 64 МиБ, свободном месте менее 64 МиБ или доступной памяти менее 64 МиБ показывается пояснение. Это диагностические пороги, а не квоты или доказательство утечки.

Снимок доступен даже при остановленном движке или недоступном Clash API. Проверка читает только метаданные одного файла и ограниченный `/proc/meminfo`: база не открывается, каталоги не обходятся, новые службы и файлы истории не создаются. Символическая ссылка на базу не раскрывает размер целевого файла. Автоматического удаления FakeIP нет, действующие сопоставления сохраняются.

Установщик смешанного канала выбирает только подходящий дополнительный движок x86_64 или aarch64_generic. Для NanoPi R4SE собран IPK Atlas Engine 1.13.21-r3 aarch64_generic; упаковщик определяет архитектуру по ELF, включая проверку длины заголовка. Пакет ARM64 пока не испытан на физическом устройстве. Для OpenWrt 24.10.1 используется IPK; ARM64 APK здесь не выпускался.

Сравнение: Podkop 0.7.23 также поддерживает XHTTP и резервы через podkop-engine r11+, поэтому эти функции являются общими. Новая доработка Atlas улучшает локальную диагностику расхода ресурсов. Исчерпывающее отсутствие аналогичных средств в Podkop и превосходство по скорости/RAM не утверждаются. Источник: https://github.com/itdoginfo/podkop/blob/0.7.23/README.md

Нет общей квоты базы FakeIP, ARM64-нагрузочных результатов и гарантии отсутствия роста памяти. Эти ограничения не устранены диагностическим снимком.

Проверки этой доработки: 354 теста на Windows, 334 успешных, 20 Linux-зависимых пропущены. Проверены кэш без открытия базы, отсутствие файла, повреждённая конфигурация, символическая ссылка, малый запас места/памяти и доступность снимка при остановке/ошибке API. Настоящий Chrome проверил desktop/mobile, включая новые показатели; RPC роутера моделируется. Новый полный Linux-набор этой версии не выполнялся.
