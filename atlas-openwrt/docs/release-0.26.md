# Atlas 0.26 beta

Устранены подтверждённые функциональные ограничения предыдущей сверки.

- Экспертный JSON может ссылаться на выходы других секций через section_<ID>_<tag>, а также на существующие общие группы, пулы и профили. detour, outbounds и default сохраняют внешние ссылки; локальные теги по-прежнему изолированы. Готовый общий граф проверяется на несуществующие/выключенные выходы, повторяющиеся теги и циклы. Можно построить последовательность прокси через несколько секций. Типы и совместимость протоколов проверяет установленный sing-box. Циклы и отсутствующие выходы дают ошибку, не прямой fallback.
- Отдельный DNS resolver можно задать вместе с портами и TCP/UDP. DNS выбирается по доменам секции и доступным признакам устройства/входа, а ограничения портов/транспорта действуют на соединения. DNS-запрос не содержит порт будущего соединения: resolver применяется к этим доменам для всех портов. Это явно объяснено в интерфейсе. dnsmasq может скрывать адрес клиента, если пересылает запрос от себя.
- В настройках есть режим «Без лимита активного пула»: max_active_nodes=0. Прежние режимы 128/256/512/1024 и значение по умолчанию сохраняются. Конфигурация с 1100 выходами проверена; это не нагрузочное испытание 1100 соединений. Пределы архива подписок, импорта и памяти устройства сохраняются.
- Проверка графа выполняется без рекурсивного обхода Python, чтобы большие цепочки не упирались в лимит глубины интерпретатора.

Подписки, независимые секции, UDP-over-TCP, URLTest, DNS/FakeIP, локальные/удалённые списки, SRS, отдельные входы, YACD, диагностика и управление службой сохраняются. Таблица функций не является доказательством всех возможных комбинаций Podkop или превосходства каждого параметра.

Скорость, RAM, длительная стабильность, внешняя многоступенчатая цепочка прокси, внешние UDP-over-TCP серверы и все архитектуры физических роутеров требуют отдельных испытаний. Резервная копия 16 МиБ, RPC и ограничения источников подписок остаются. APK не подписан публичным ключом репозитория; проверка SHA256 установщиком не заменяет доверенную подпись. GitHub Releases и raw-зеркало — один провайдер.

303 автоматических сценария: Windows с sing-box 1.12.17 — 288 успешно, 15 пропущено; Linux — 292 успешно, 11 пропущено. Chrome проверил сохранение resolver с портами и режима max_active_nodes=0, прежние сценарии и мобильную ширину (RPC заменён моделью). OpenWrt 25.12.0 / sing-box 1.13.21: проверка конфигурации с межсекционным detour и DNS/портами, статическая проверка 1100 выходов, реальный запуск/остановка и восстановление WAN — 21 синтетическое событие, один обработчик и один перезапуск. Внешний трафик многоступенчатой цепочки не испытан. Повторение: tests/test_section_links.py и tests/native_sections_026.py.

Дополнительно выполнена реальная локальная передача HTTP-запроса через SOCKS-секцию и HTTP-прокси другой секции к тестовому серверу. Получен ожидаемый ответ; оба промежуточных узла подтвердили прохождение запроса. Использован штатный mixed-вход и правила секции, без создания тестового TUN. Внешние сети не использовались. Повторение: tests/native_chain_026.py.
