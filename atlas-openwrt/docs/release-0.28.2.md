# Atlas 0.28.2 — проверка ограничений и защита от повторов

Запросы монитора из таймера, кнопки и навигации объединяются, пока запрос выполняется. По завершении, включая ошибку, ограничитель освобождается. Это не добавляет очереди и истории.

Выбор сервера прекращается с policy-block, если ранжирование возвращает ключ вне оставшихся кандидатов. Так исключён цикл без сокращения списка при нарушении внутреннего контракта. В штатном ранжировании такой случай не воспроизводился; добавлена защитная проверка и регрессия.

Проверены существующие ограничения: четыре HTTPS-проверки за цикл, две одновременные проверки в движке без очереди, таймаут проверки до пяти секунд, максимум 4096 временных подтверждений, лимит ответа Clash API и ограниченный вывод соединений/правил. Процессы диагностики завершаются в finally; procd ограничивает короткие неудачные перезапуски. Обработчик событий интерфейсов объединяет события под блокировкой, но при непрерывных событиях ожидание может продолжаться — это не обещание фиксированного времени восстановления.

355 тестов Windows: 335 успешных, 20 требуют Linux и пропущены. Пройдены DOM-проверки объединения запросов и повторного запроса после завершения, Chrome desktop/mobile с моделью RPC. Новый многосуточный тест и запуск ARM64 на NanoPi не выполнялись.

Не устранены: общая квота базы FakeIP, возможность увеличения рабочей памяти с числом доменов/соединений, расход памяти при отключённом пользователем лимите файла списков. Рост размера базы сам по себе не доказывает утечку. Нулевые утечки и отсутствие любых ошибок не гарантируются.
