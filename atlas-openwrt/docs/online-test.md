# Интернет-стенд OpenWrt через QEMU

QEMU запускает обычный OpenWrt x86-64 как виртуальную машину на Linux ПК. Его user-mode NAT даёт гостю TCP/UDP выход в интернет без bridge или физического роутера. В стандартной схеме OpenWrt использует `eth1` как WAN, а QEMU выдаёт ей DHCP адрес. Это соответствует [официальной инструкции OpenWrt для QEMU](https://openwrt.org/docs/guide-user/virtualization/qemu).

## Что понадобится

- Linux-компьютер с интернетом и 4 ГиБ свободной RAM.
- QEMU x86-64, `scp`, официальный OpenWrt x86-64 образ `combined-ext4` и файл Atlas `.ipk`.
- OpenWrt 24.10+ на `opkg`; образ 24.10.7 использовался для предыдущей установки Atlas. Не подключайте эту тестовую VM к домашней LAN.

Установите QEMU (Debian/Ubuntu):

```sh
sudo apt update
sudo apt install qemu-system-x86 openssh-client e2fsprogs
```

Скачайте образ и его `sha256sums` из одного каталога официальных выпусков OpenWrt. Проверьте образ контрольной суммой до запуска; не используйте файл, который не проходит эту проверку. QEMU по умолчанию применяет snapshot, поэтому изменения диска не переживают остановку.

## Запуск

Из каталога `atlas-openwrt` выполните:

```sh
sh tools/openwrt-qemu-internet.sh /path/to/openwrt-x86-64-combined-ext4.img dist/luci-app-atlas_0.13.0-1_all.ipk
```

Скрипт создаёт отдельный временный образ с 512 МиБ ext4, исходный файл не меняется. Откроется консоль OpenWrt. Первый раз задайте root-пароль командой `passwd`. Скрипт подключает `eth0` к тестовой LAN и `eth1` к отдельному QEMU NAT. LuCI будет доступна только на хосте по `http://127.0.0.1:8080`; гостевой SSH проброшен на `127.0.0.1:2222`.

В другом терминале отправьте пакет в гостевую систему и установите его:

```sh
scp -P 2222 dist/luci-app-atlas_0.13.0-1_all.ipk root@127.0.0.1:/tmp/atlas.ipk
ssh -p 2222 root@127.0.0.1 'opkg update && opkg install /tmp/atlas.ipk'
```

В консоли OpenWrt проверьте WAN и HTTPS:

```sh
ip -4 addr show dev eth1
ip route
wget -O /dev/null https://www.gstatic.com/generate_204
```

Используйте HTTPS, а не `ping`: QEMU user-mode networking в общем случае не пропускает ICMP. Установка пакета через `opkg` дополнительно проверит, что OpenWrt VM может скачать зависимости.

## Проверка Atlas и подписки

1. Откройте LuCI на хосте `http://127.0.0.1:8080`, войдите в систему и добавьте подписку через экран Atlas. Ссылка обрабатывается внутри гостевой системы.
2. Обновите подписку и убедитесь, что импортированы профили без ошибок.
3. Нажмите **Проверить серверы**, затем примените Atlas и проверьте доступ из гостя через LuCI. Для проверки узла используйте HTTPS probe Atlas; у QEMU NAT нет надёжного ICMP ping.
4. Проверьте выбранный выходной IP с устройства, подключённого к гостевой LAN, либо используйте встроенное сравнение IP. Встроенная проверка делает запросы к `api.ipify.org` напрямую и через один узел и сохраняет только результат сравнения.
5. Для сценария failover используйте несколько доступных профилей одного пула, остановите текущий сервер или отключите маршрут к нему и дождитесь интервала URLTest. Статус Atlas должен показывать фактически выбранный движком узел.

Если гостю выдан адрес на `eth1`, но HTTPS не проходит, проверьте время системы, default route и DNS. Не открывайте LuCI порт на внешний интерфейс хоста. Остановите VM сочетанием `Ctrl-A`, затем `X`.

## Что тест подтверждает

Он проверяет установку пакета в OpenWrt, выход VM в интернет, получение зависимостей, загрузку подписки, обработку профилей, запуск sing-box и HTTPS через профиль. Он не проверяет Wi-Fi радиомодули, производительность ARM/MIPS роутера, работу firewall на вашей конкретной прошивке или географию выходного IP. Для финального приёмочного теста установите тот же `.ipk` на целевой роутер и проверьте клиентское устройство за его LAN.
