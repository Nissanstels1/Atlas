# Atlas 0.27.0 beta

Реализованы четыре пробела, найденные при сравнении с Podkop 0.7.23:

- Упорядоченный резервный набор URLTest для общего пула и отдельных секций. Резерв используется только при недоступности основных серверов; после восстановления группа возвращается к основным. Резервные профили выбираются из импортированных источников; ссылки предварительно импортируются в менеджере профилей.
- Проверка скачивания 64 КиБ перед переключением: настройка движка по умолчанию, выключение или собственный HTTPS URL. Проверка выполняется расширенным движком, а не таймером LuCI.
- Импорт VLESS/Trojan xhttp и splithttp, включая исходное URL-кодирование extra. Ссылку разбирает движок; результат проходит нормализацию и проверку конфигурации перед применением.
- Определение Features установленного движка. Неподдерживаемые настройки не применяются молча; интерфейс показывает возможности и отключает добавление неподдерживаемых опций.

## Движок

Готовый podkop-engine и podkop-engine-full не содержат TUN. Atlas использует TUN, поэтому собран отдельный **atlas-engine 1.13.21-r1** с TUN и расширениями URLTest/XHTTP. Он основан на SagerNet sing-box v1.13.21 и серии из 86 патчей FiyeroT/podkop-engine v1.13.21-r12. Сборка не связана с авторами исходных проектов; лицензия GPL-3.0-or-later. Сохраняются исходники, лицензии, зависимости и рецепт сборки.

Движок устанавливается отдельно в `/usr/lib/atlas-engine/bin/atlas-engine`, без замены `/usr/bin/sing-box` и без дополнительной фоновой службы. Atlas выбирает его при наличии; после установки примените настройки или перезапустите Atlas. Штатный sing-box остаётся необходимой зависимостью основного пакета и резервным вариантом после удаления дополнительного движка. Для возвращения к штатному движку сначала очистите расширенные параметры и xhttp-профили. Повторный запуск с несовместимой конфигурацией будет отклонён.

Готовые пакеты дополнительного движка предназначены **только для OpenWrt x86_64**. Это статическая Linux amd64 сборка без CGO и NaiveProxy. Она не устанавливается на ARM/MIPS; проверка таких устройств не выполнена. Автоматического скачивания или замены движка на пользовательском роутере нет.

Для IPK/OpenWrt с opkg: основной `luci-app-atlas_0.27.0-3_all.ipk` и дополнительный `atlas-engine_1.13.21-1_x86_64.ipk`. Для APK/OpenWrt с apk: `luci-app-atlas-0.27.0-r3.apk` и `atlas-engine-1.13.21-r1.apk`. APK локальные и не подписаны доверенным публичным ключом: при установке нужен явный `--allow-untrusted`. Контрольные суммы приложены отдельно. Дополнительный движок занимает место рядом со штатным; меньший расход flash не заявляется.

## Проверки и ограничения

Автоматические проверки: 333 теста на Linux без пропусков; Windows — 316 успешных, 17 требуют Linux. Chrome: формы desktop/mobile и сохранение резервного профиля/URL скачивания; RPC моделируется.

В виртуальной OpenWrt 25.12 x86/64 проверены настоящим расширенным движком: полная конфигурация с TUN, декодирование xhttp/splithttp, скачивание 65536 байт через контролируемый прокси, пропуск первого мёртвого резервного сервера и выбор следующего, возврат к основному после восстановления. Это локальные контролируемые серверы; внешний XHTTP-сервер и физический роутер не испытывались. Также проверяется запуск службы Atlas с установленным дополнительным пакетом.

Расширенные настройки URLTest работают в нативном режиме «Самый быстрый», без приоритета стран, стратегии стабильности/самого медленного и порогов пинга. Совмещение отклоняется явно, чтобы нативный URLTest не обходил критерии Atlas. Обычные фильтры допустимы, но резерв должен оставаться в выбранном активном пуле. Требуется минимум один основной сервер. Для экспертной секции те же параметры задаются в JSON; ссылки `fallbacks` включены в проверку графа и изоляцию имён.

Обработчик резервных серверов и проверка скачивания принадлежат расширенному движку. Новые параметры не превращают Atlas в программу без лимитов памяти и не доказывают превосходство по всем показателям. Скорость, CPU/RAM, IPv4/IPv6-утечки, многосуточная устойчивость и поддержка всех версий OpenWrt требуют сопоставимых испытаний. Результаты нагрузки 0.26.1 нельзя автоматически считать измерениями новой версии или нового движка.

Отдельно испытан окончательный Atlas 0.27.0-r3 с Atlas Engine на том же виртуальном стенде: 12 запусков, 2012 успешных HTTP-запросов и 2012 DNS-запросов, сохранение FakeIP и отклонение устаревшего выбранного узла. На повторных 1000 запросах к известным доменам кэш оставался 256 КиБ, RSS — 29.02–29.56 МиБ; активных завершённых HTTP-соединений не осталось. Это наблюдение ниже диапазона 41.86–42.66 МиБ прежнего Atlas со штатным движком в аналогичном коротком сценарии, но не сравнение с Podkop и не гарантия отсутствия утечек. База может увеличиваться при новых доменах; глобальной квоты нет.

Повторный UDP-тест нового движка при постоянной смене клиентских сокетов доставил 800 запросов; два потребовали повторной отправки после таймаута. Дескрипторы оставались на уровне 11, исчерпания не обнаружено. Причина первых таймаутов не установлена; этот вопрос остаётся открытым. Длительная устойчивость и отсутствие любых таймаутов не заявляются.

Пакеты этого выпуска подготовлены локально; публикация GitHub в этой задаче не выполнялась.
