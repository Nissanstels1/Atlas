# Исправления запуска и переноса Podkop

Эти изменения находятся в исходниках после выпуска 0.28.3. Опубликованные пакеты 0.28.3 их пока не содержат.

Общие входные интерфейсы Podkop переносятся в `capture_interfaces` Atlas. Например, `br-lan` ограничивает основной TUN и его автоматический перехват входящим LAN-трафиком. Это отдельный параметр от входного интерфейса конкретной секции. Пустой массив сохраняет прежний режим перехвата. В LuCI параметр доступен в настройках LAN.

Секция с внешними списками и ограничением входного интерфейса больше не создаёт неявное правило для всего трафика этого интерфейса перед списками. Правила без списков, явно заданные только по интерфейсу, продолжают работать.

Прокси каждой секции, её домены, подсети, общественные и удалённые списки должны сохранять собственную привязку к серверу. Полностью маршрутизируемые устройства требуют отдельного правила по адресу источника: объединение адреса источника с доменами в одной секции меняет смысл на пересечение условий. Остальной трафик сохраняет маршрут direct.

Диагностика отдельного сервера теперь исключает ссылки на подписочные пулы и списки основной конфигурации. При ошибке создания тестового процесса журнал закрывается. Проверка DNS принимает как NXDOMAIN, так и NOERROR без адреса (EAI_NODATA), сохраняя отказ при временной ошибке резолвера.

Чтение dnsmasq игнорирует посторонние многострочные параметры и сохраняет все значения списка server. Если интеграция DNS выключена и её резервной копии нет, запуск не читает и не меняет конфигурацию dnsmasq.

При переключении между системами с FakeIP клиенты могут хранить адреса предыдущего движка. Перед переносом совместимого кеша оба использующих его процесса необходимо остановить, сохранить исходные файлы и проверить новый движок; копировать рабочую базу поверх открытого файла нельзя. Успешный запуск службы сам по себе не подтверждает доступ клиентов в интернет.

DNS серверов включённых удалённых списков возвращает реальные адреса через выбранный защищённый резолвер до правил FakeIP. Для списков GitHub Releases учтён сервер перенаправления `release-assets.githubusercontent.com`. Загрузка по-прежнему использует выбранную секцию через защищённый локальный list-fetch listener. Проверка публичных адресов и запрет перенаправления HTTPS на HTTP сохраняются; произвольные перенаправления на частные адреса не разрешаются.

Проверки: 370 Linux-тестов, 18 явных пропусков; проверка DOM LuCI. В изолированной OpenWrt 25.12.0 отдельный LAN-клиент через veth/TUN получил HTTPS-ответы для direct и двух разных секций. На физическом NanoPi R4SE с OpenWrt 24.10.1 реальные импортированные VLESS-профили предварительно проверены через отдельный loopback listener с сохранением работающего Podkop. При окончательном переключении Wi-Fi-клиент получил HTTPS 200 для OpenWrt, GitHub, YouTube и Discord, а Google Static — 204. API действующего Atlas подтвердил адрес источника этого клиента и direct для OpenWrt/Google Static, секцию main для GitHub/YouTube/Discord. YouTube попал в main также в исходном Podkop из-за пересечения списков; приоритет не изменён ради искусственного выбора секции Yotube. Все 12 проверок диагностики и загрузка всех девяти списков через прокси прошли. Это проверка указанной конфигурации и сайтов, а не гарантия всех устройств, протоколов или длительного отсутствия роста памяти.
