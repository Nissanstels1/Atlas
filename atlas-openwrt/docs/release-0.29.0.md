# Atlas 0.29.0 beta — группы сайтов и пошаговая настройка

Маршрутизация строится вокруг групп: сайты, назначенные списки, подключение и условия проверки находятся рядом. Сложные условия, старый текстовый редактор и диагностика раскрываются отдельно. Существующие настройки сохраняются; прежний порядок правил действует до явного включения нового порядка. Мастер добавляет новую группу первой и объясняет это перед сохранением.

Мастер задаёт шесть вопросов: подключение, сайты, маршрут, выбор профиля, общие DNS/маршрутизация и итог. Доступны готовые наборы YouTube и HDRezka. Прямая группа и блокировка не требуют подписки. Для HDRezka следует указать фактическое HTTPS-зеркало, если нужна проверка именно сайта.

## Независимый подбор профилей

У каждой обычной прокси-группы можно задать до трёх HTTPS-проверок: допустимые успешные HTTP-коды и необязательный текст первых 64 КиБ страницы. Все проверки должны пройти. Например, группа YouTube проверяет youtube.com, группа HDRezka — используемое зеркало. Ручной выбор не переключается автоматически. При отсутствии подходящего профиля группа блокируется, без незаметного перехода напрямую.

Проверки выполняются постепенно: до четырёх кандидатов на цикл проверок сайтов, общий срок 22 секунды и ограниченная очистка дочерних процессов. Следующий цикл продолжает поиск после неудачных кандидатов; группы получают очередность. Результаты имеют срок действия и лимит 4096 записей. Содержимое ответов не сохраняется. Проверка страницы не подтверждает воспроизведение видео, вход в аккаунт или отсутствие CAPTCHA. Планировщик работает примерно раз в минуту; указанный интервал не является гарантией точного времени переключения.

## Безопасность

Новая карточка сравнивает выход браузера с измеренными выходами роутера и показывает подтверждённое совпадение, прямой выход, различие либо непроверенный результат. Для сравнения нужны свежие измерения и неизменённая конфигурация. Браузерные IP передаются только своему роутеру для сравнения и не записываются в состояние. На роутере сохраняются отпечатки измеренных выходов.

WebRTC/STUN включается отдельно с пояснением внешнего сервера. Камера и микрофон не запрашиваются. Недоступная проверка не означает отсутствия утечки. Без отдельного измерения IPv6 статус остаётся непроверенным. Внешняя проверка DNS открывается явно пользователем. Локальный просмотр признаков браузера показывает язык, часовой пояс и другие доступные признаки; полной анонимности это не гарантирует.

## Исправления

Исправлена ошибка «Некорректное число правил списка» при изменении маршрутизации: служебные счётчики и признаки кеша берутся из сохранённого состояния с правильными типами. Названия групп можно менять без потери загруженных правил. Новый порядок включает назначенные списки в приоритет своей группы и согласует порядок DNS.

Этот выпуск также содержит ранее проверенные исправления миграции Podkop, FakeIP, загрузки списков и ограничения захвата LAN.

## Проверка и ограничения

Проверены тесты сохранения списков, порядка групп и DNS, разделения критериев двух сайтов, ограничений повторных попыток, устаревших результатов безопасности и прохождения мастера. На виртуальной OpenWrt 25.12 выполнены тесты с Atlas Engine r3, а также реальные HTTPS-проверки сайта с правильным/неправильным текстом, HTTP-кодом и абсолютным лимитом времени. DNS тестового домена получен через HTTPS DNS, чтобы исключить FakeIP компьютера.

Новые функции ещё не испытывались на физическом NanoPi. Ранее на NanoPi R4SE/OpenWrt 24.10.1 подтверждена работа мигрированной маршрутизации и интернета. Этот факт не заменяет проверку нового выпуска на устройстве. Длительные испытания памяти и сравнение производительности с Podkop не выполнены.
