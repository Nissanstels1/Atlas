# Atlas 0.16.0 beta

Целевая платформа: OpenWrt 24.10.1 и новее, fw4, Python 3 и sing-box 1.12+. Версия beta: новый код ещё не установлен и не проверен на физическом роутере.

## Реализованные изменения

- Независимые HTTP/SOCKS-входы секций: отдельный порт, адрес и обязательные учётные данные. Запросы направляются в выход своей секции; секция без обычных условий не превращается в правило для всего трафика. Адрес ограничен loopback/private, порты проверяются на конфликт внутри Atlas.
- Администраторский редактор sing-box JSON: одиночный выход либо граф до 64 выходов с selector, urltest и detour. Первый выход — точка входа. Ссылки и циклы проверяются; теги изолированы по секциям. Движок проверяет конфигурацию до сохранения. Произвольные протокольные поля доступны только через явный локальный редактор; удалённые подписки сохраняют строгий фильтр.
- Редактирование локальных JSON-профилей с сохранением источника и идентификаторов неизменённых профилей. Некорректное редактирование не заменяет исходные данные частично.
- Формы секций вместо обязательного текстового синтаксиса: порядок, включение/отключение, домены, сети, устройства, интерфейсы, порт/диапазон, TCP/UDP, собственный DNS, пул и JSON. Старый формат доступен в раскрываемом блоке.
- Независимые секции могут работать без основного пула; основной выход тогда блокируется. DNS и предварительное разрешение реальных IP учитывают конкретную секцию и её resolver.
- Экспорт/восстановление настроек и профилей. Восстановление допускается при остановленной службе, проходит проверку формата и движка, сохраняет предыдущий state. Доказательства страны выхода сбрасываются; строгие фильтры остаются включёнными. Резервная копия содержит секреты, её нужно хранить как пароль.
- Диагностический экспорт с ограниченным набором полей: версии, счётчики, флаги и результаты проверок. Без профилей, паролей, URL подписок, адресов соединений и сырых журналов.
- Ограниченная параллельная проверка серверов с учётом памяти, изоляция проверочного кеша, фильтрация TCP/UDP и портов из 0.15 сохранены.
- Ускорена проверка больших списков: устранены квадратичные поиски дубликатов и повторная внутренняя валидация уже проверенных настроек.
- Подготовлена нативная сборка IPK/APK через официальный SDK: загрузка с проверкой SHA256, ручной workflow для 24.10.1/25.12.0 и локальный установщик с проверкой контрольной суммы. Нативная сборка SDK и APK здесь не запускались.

## Проверка

Windows, Python 3.12.14: 220 тестов, 209 успешных, 11 явно пропущены без включения платформенных интеграционных проверок. Пропуски включают POSIX-права и OpenWrt/движок. Для Windows используется адаптер файловой блокировки; это не проверка Linux flock.

Отдельный настоящий sing-box 1.12.17 и 1.14.2: два независимых аутентифицированных входа доставляют запросы в разные локальные выходы; запрос без пароля получает 407; обычный вход не попадает в эти секции. Всё выполнялось на localhost, без доступа к провайдеру. Linux TUN заменён тестовым входом, поэтому fw4, dnsmasq, WAN и клиентские утечки не проверены.

Два набора браузерных проверок успешны: существующие экраны и новые формы/JSON/порядок/редактирование профилей/диагностика. Новые формы проверены настоящим Chrome, включая ширину 390 px; RPC роутера подменён тестовыми ответами. Синтаксис установщика проверен, сам установщик не выполнялся.

Попытка включить старые платформенные интеграционные тесты на Windows дала семь ошибок: Windows запрещает чтение открытых NamedTemporaryFile, а Linux auto-redirect не инициализируется на Windows. Эти тесты не считаются успешными; они требуют Linux/OpenWrt. Новые отдельные loopback-проверки двух версий движка успешны.

На фиксированной нагрузке из пяти списков по 10 000 уникальных доменов медиана валидации уменьшилась с 1.395 с (предоставленный исходник 0.14) до 0.216 с: примерно 6.46 раза. Три повтора, Windows/Python 3.12.14; данные в validation-benchmark-0.16.json. Это сравнение Atlas с исходным Atlas, а не скорость туннеля или сравнение с Podkop.

## Сравнение с Podkop и границы результата

Проверены первичные источники: https://github.com/itdoginfo/podkop, https://podkop.net/docs/sections/, https://podkop.net/docs/settings/, https://podkop.net/docs/install/.

| Параметр | Результат Atlas 0.16 |
|---|---|
| Отдельный mixed-прокси секции | Реализован и проверен реальным движком |
| JSON-выходы, selector/urltest/detour секций | Реализованы; финальная схема проверяется установленным движком |
| Управление подписками, локальными профилями, геофильтрами и замерами | Сохранено; расширено редактирование |
| Порты/диапазоны, TCP/UDP, split DNS и независимые пулы | Реализованы, логика проверена |
| Удобство интерфейса | Формы и мобильная компоновка проверены; пользовательского сравнительного исследования нет |
| Резервное копирование и диагностический экспорт | Реализованы; восстановление не запускает службу автоматически |
| IPK | Собран вручную и проверен по структуре; установка 0.16 на OpenWrt не проверена |
| APK | Подготовлена SDK-сборка; готового и проверенного APK нет |
| RAM, flash, CPU, скорость трафика и надёжность на роутере | Сравнительных измерений с Podkop нет |
| OpenWrt 24.10.1+, ARM/MIPS, TUN/fw4, обновления и перезагрузка | Требуется проверка новой версии на этих системах |

Утверждать превосходство по всем параметрам нельзя: Python-зависимости могут требовать больше flash/RAM, а функциональная возможность сама по себе не доказывает более высокую скорость и стабильность. Неизвестные будущие версии OpenWrt не имеют гарантированной совместимости. Список новых возможностей реализован; завершение нативной APK-сборки и аппаратных сравнений требует Linux SDK и роутера.

## Установка

На OpenWrt с opkg используйте luci-app-atlas_0.16.0-1_all.ipk. Сохраните резервную копию роутера и настроек Atlas, проверьте свободное место и наличие sing-box >=1.12. Установка пакета не подтверждает маршрутизацию: после установки проверьте конфигурацию, запустите службу и выполните самопроверку с клиентского устройства. IPK нельзя устанавливать через apk.

Исходники содержат tools/install-package.sh и SHA256SUMS. Скрипт запускается на роутере от root с путями к пакету и manifest; он сохраняет предыдущий state и не запускает Atlas. Для OpenWrt с apk сначала нужно собрать нативный APK через SDK. Для будущих обновлений/API движка используйте предварительную проверку конфигурации.
