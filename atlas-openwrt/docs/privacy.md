# Изменения приватности Atlas 0.14.0

- Критерии выбора применяются к общему селектору и каждому независимому пулу. Нет свежего подходящего замера — группа выбирает блокирующий outbound; новые соединения отклоняются, старые прерываются. Выбор обновляется раз в минуту. В ручном режиме ограничения ping не применяются к главному селектору.
- В таком режиме FakeIP сохраняется. При каждом запуске процесса, включая procd respawn, Atlas меняет пространство кеша выбора узла: прежний выбор не восстанавливается, группы начинают с блокировки до свежего подходящего замера.
- FakeIP охватывает доменные разделы и удалённые доменные/SRS списки. Блокировки DNS и исключения имеют приоритет; явный DNS resolver раздела сохраняет своё поведение. Разделы с одновременным условием CIDR назначения не получают доменное правило FakeIP.
- Повторное разрешение выполняется действием route resolve через secure непосредственно перед маршрутом proxy. Bootstrap адресов серверов остаётся отдельным, чтобы не создавать DNS цикл.
- Базовый IP для сравнения измеряется из изолированного процесса с outbound, привязанным к активному l3_device WAN. При отсутствии WAN тест заканчивается ошибкой без обходного маршрута.
- Проверка браузера выполняется только по нажатию: HTTPS к api.ipify.org и api6.ipify.org; локальный сбор WebRTC ICE без STUN. Ответы остаются в памяти страницы. Недоступность IPv6 не доказывает отсутствие утечки. DNS/DoH, WebRTC через STUN и отпечатки браузера этот тест не измеряет.

Ни одна из этих проверок не доказывает анонимность. Страны по названиям профилей не являются геолокацией; включайте проверку IP и строгий фильтр, когда нужна подтверждённая страна выхода.

# Настройки и проверки, доступные с 0.12.0

## Доступные настройки

- DNS клиентских запросов перехватывается TUN и отправляется к Cloudflare DoH через выбранный proxy outbound.
- В настройках можно переключить DoH на фильтрующий публичный AdGuard DNS. AdGuard заявляет блокировку рекламы и трекеров на своем DNS-сервисе; выбранный DNS-провайдер получает запросы доменов.
- В разделе маршрутизации можно добавить собственные домены в DNS-блокировку. Правило отвечает `REFUSED`; это не сетевой фильтр для прямого IP-доступа.
- FakeIP можно включить для доменов через прокси или для всех DNS-запросов в глобальном режиме. Клиентам возвращаются адреса из зарезервированных диапазонов sing-box FakeIP, а сопоставление используется при маршрутизации.
- FakeIP TTL настраивается от 1 секунды до суток; значение по умолчанию 60 секунд помогает клиентам забывать устаревшие синтетические адреса после перезапуска роутера.
- По желанию sing-box повторно разрешает маршрутизируемые домены через выбранный защищённый resolver. Это снижает риск передать синтетический FakeIP upstream outbound; проверяется опцией `resolve_real_ip` и self-test.
- Секции proxy/direct/interface могут направлять DNS-запросы своих доменов на отдельный UDP/DoT/DoH сервер по тому же маршруту, что и трафик секции. UDP не шифруется; DoT/DoH проверяют TLS сертификат DNS-сервера.
- Входной интерфейс LAN можно привязать к секции; текущие IPv4/IPv6 подсети интерфейса становятся критерием источника. Это избавляет от ручного списка клиентских IP при маршрутизации VLAN.
- Дополнительный fail-closed переключатель устанавливает fw4 правило LAN→WAN. Оно блокирует переход на прямой WAN, если TUN маршрут Atlas исчезает; локальная сеть и исходящие соединения самого роутера остаются доступны. Выключите опцию в Atlas, если хотите разрешить обычную маршрутизацию после остановки Atlas.
- Локальные UTF-8 `.txt`, `.lst` и `.json` списки можно импортировать как proxy, direct или block правила. Содержимое отправляется аутентифицированному RPC роутера и сохраняется в конфигурации Atlas; предел размера файла — 64 КиБ.
- ECS (EDNS Client Subnet) Atlas не задаёт.
- Опциональная интеграция dnsmasq перенаправляет DHCP DNS на loopback DNS listener Atlas. Перед применением сохраняются прежние UCI значения `server`, `noresolv` и `cachesize`; при остановке восстанавливаются только параметры, которые не менялись вручную. Для клиентов со статическим DNS эта настройка не действует.
- Вкладка «Монитор соединений» читает локальный Clash API и показывает до 50 потоков, сработавшие правила, RSS sing-box из procfs и счётчики трафика. Доступ разрешён только ACL администратора LuCI; токен не передаётся в браузер, endpoint доступен только на loopback.
- Приватные заголовки авторизации подписки скрыты из статуса. Перенаправления на другой HTTPS origin блокируются, чтобы токен не ушёл стороннему домену. Запросы используют ETag и Last-Modified отдельно от введённых заголовков.
- Кеш можно хранить в RAM, flash или внешнем USB mount. При внешнем режиме Atlas проверяет, что путь проходит через реально смонтированный том под `/mnt` или `/media`; настройки и ссылки подписок остаются в `/etc/atlas`.

## Проверка приватности

Экран **Приватность** показывает конфигурационные признаки и отдельную функциональную самопроверку: sing-box check, процесс, loopback API, TUN, firewall4 fail-closed, перехват DNS, TLS resolver, новый DNS lookup через системный резолвер OpenWrt и HTTPS запрос через выбранный прокси. Отдельная проверка FakeIP посылает новый DNS A запрос прямо к 127.0.0.1:53, чтобы проверить связку dnsmasq → Atlas. Ответ должен содержать адреса только из 198.18.0.0/15. В глобальном режиме используется случайное имя в example.com; в режиме правил — поддомен первого доменного правила FakeIP без ограничения источника. Без такого домена проверка сообщает, что нужен тестовый домен. DNS проверка подтверждает ответ резолвера, но не анализирует packet capture и не определяет, какой рекурсивный оператор фактически видел запрос. Это проверка роутера, не браузера или каждого клиентского устройства.

Внешняя проверка IP запускается явным нажатием. Atlas делает два HTTPS-запроса к `api.ipify.org`: один напрямую с роутера, второй через один выбранный узел. Сервис проверки видит оба адреса. Atlas не записывает сами адреса — сохраняет только время, успешность и совпали ли результаты. Проверка одного узла не тестирует весь автоматический пул или трафик клиентского устройства.

## Границы защиты

Bootstrap DNS настраивается как DoH или DoT к заданному IP адресу; по умолчанию Cloudflare видит имена серверов, к которым подключается роутер. FakeIP сохраняется в cache file с правами каталога Atlas. При строгом автовыборе кеш выбора узла изолируется на каждом запуске; при штатном URLTest действует обычный кеш. RAM-кеш не переживает перезагрузку роутера. Atlas не блокирует неизвестные клиентские DoH серверы, ECH, WebRTC или приложения с отдельным VPN; не изменяет browser fingerprint. Watchdog выполняет ограниченные попытки рестарта и восстанавливает последнюю проверенную конфигурацию, если активная конфигурация повреждена. Fail-closed защита блокирует LAN→WAN fallback, но сама по себе не обеспечивает доступность прокси и не блокирует исходящие запросы роутера. В режиме «По правилам» неуказанный трафик идёт напрямую через policy engine. Удалённый DNS-провайдер и прокси видят запросы и соединения, переданные им согласно их роли. Поэтому функции снижают часть утечек и трекинга, но не делают пользователя анонимным.

Конфигурации FakeIP+AdGuard, custom sing-box JSON outbound, реального IP разрешения, per-section DNS, DNS listener для dnsmasq и SRS должны проходить `sing-box check` на установленной версии движка. Обновление списков можно направить через закрытый аутентифицированный loopback proxy к общему или выбранному подписочному пулу; HTTP(S) загрузчик не включает прямой fallback при включённой опции. Внешний IP-тест посылает запросы к `api.ipify.org` напрямую и через узел, а затем сохраняет лишь сравнение. Проверка браузерных утечек и анонимности остаётся клиентским тестом.

## Проверенная страна выхода

На вкладке серверов есть отдельная проверка страны. HTTPS запрос к `https://ipapi.co/country/` проходит через проверяемый профиль во временном локальном прокси с проверкой TLS; прямого fallback нет. Сервис видит выходной IP; Atlas сохраняет только двухбуквенный код и время. Статус показывает, взята ли страна из названия или получена внешней проверкой. Это геолокация базы сервиса, а не доказательство физического местоположения оборудования.

Результат действует 30 дней и сохраняется при обновлении неизменившегося профиля. Страновой фильтр может требовать свежую проверку; тогда неизвестные, истёкшие и неподтверждённые страны не допускаются. Новая проверка применяет страновые ограничения к работающему пулу. Если пул становится пустым, Atlas включает LAN fail-closed, останавливает службу и отключает её автозапуск, чтобы watchdog не восстановил запрещённый выход. Строгая политика также проверяется минутным watchdog и при холодном старте. После изменения допустимого пула службу запускают вручную.

## Диагностика FakeIP браузера

Выключена по умолчанию. Включение создаёт точные DNS/route правила только для двух диагностических доменов. HTTPS к fakeip.podkop.fyi идёт напрямую на порт 8443; HTTPS к ip.podkop.fyi идёт через proxy. Это явное исключение из глобального проксирования. Внешние сервисы получают соответствующие IP. Кнопка сравнивает ответы, сохраняет результат только в памяти страницы и отличает недоступность проверки от отрицательного результата. Тест не доказывает отсутствие всех DNS/DoH/WebRTC утечек.

Применение настроек считается успешным только после ответа API sing-box, а не по одному статусу процесса procd. При недоступном API конфигурация не отмечается применённой и используется штатный откат.
