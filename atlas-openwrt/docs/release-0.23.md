# Atlas 0.23 beta

Закрыты пять недостатков повторного функционального аудита Atlas 0.22:

- Разрешение реального IP задаётся отдельно для секции: наследовать общее значение, включить или выключить. Настройка распространяется на правила секции, назначенные ей списки и её отдельный HTTP/SOCKS вход. Секции с общим пулом могут иметь разные значения.
- У обычной прокси-секции есть собственные URL автопроверки, интервал и допустимая разница задержек. Заполненные параметры создают независимые URLTest и selector для выбранной подписки либо общего набора серверов. Ручной выбор и возврат в Авто не меняют соседние секции. Общие фильтры серверов и ограничения страны сохраняются. В экспертном JSON параметры URLTest задаются самим JSON; противоречащие настройки формы отвергаются.
- Событие подъёма выбранного WAN запускает отдельный обработчик с регулируемой задержкой 0–60000 мс, по умолчанию 2000 мс. Обработчик ждёт вне блокировки, объединяет устаревшие события и соблюдает существующий предел трёх автоматических перезапусков за десять минут. Минутный планировщик остаётся резервным механизмом; событие не требует ожидать его очередного запуска. Во время пользовательской операции восстановление откладывается.
- Автоматическое восстановление и ручной запуск используют одинаковый предел команды перезапуска — 90 секунд. Успешный запуск не ждёт весь этот срок. Восстановление считается успешным только после ответа API движка, а не по запуску процесса procd.
- Интерфейс разрешает запуск конфигурации с включёнными списками JSON или секциями direct/block/exclude без подписок на прокси. Отсутствующий основной прокси остаётся блокирующим; не добавляется скрытый прямой fallback. Для явно прямой/блокирующей конфигурации DNS работает напрямую; при наличии правил, требующих отсутствующий прокси, такой DNS-обход не добавляется.

Дополнительно увеличен импорт UTF-8 списков из браузера с 64 КиБ до 4 МиБ. Размер проверяется в интерфейсе, после декодирования на роутере и отдельным пределом RPC. Большие списки по-прежнему можно подключать по URL/file:///.

Старые настройки наследуют общие значения. Сохранение старым клиентом сохраняет ранее заданные параметры секций. Резервная копия содержит новые поля.

Проверено 286 автоматических сценария: Linux с sing-box 1.12.17 — 275 успешно, 11 пропущено; Windows — 271 успешно, 15 пропущено. Chrome: новые параметры секции и WAN, импорт больше 64 КиБ, JSON-only запуск, прежние сценарии и мобильная ширина прошли. Windows-проверки не заменяют Linux TUN/procd испытания.

Полное превосходство над Podkop по всем параметрам не заявляется. Виртуальные испытания не измеряют физическую пропускную способность, RAM, реальное переключение провайдера или длительную сравнительную стабильность. Сохраняются ограничения RPC, резервной копии 16 МиБ, удалённых прокси-профилей и внешних detour между независимыми секциями. Возможности JSON определяет установленный sing-box. GitHub Releases и raw.githubusercontent.com относятся к одному провайдеру.

В виртуальной OpenWrt 25.12.0 с sing-box 1.13.21 проверены реальные независимые selector/URLTest группы, секционное разрешение IP, запуск/остановка и восстановление по синтетическому событию ifup при остановленном cron. Проверен ответ API движка после восстановления. Это тест события netifd в VM, а не обрыв физического подключения провайдера. Испытание воспроизводится tests/native_sections_023.py.
