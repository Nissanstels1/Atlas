# Atlas 0.18 beta

Цель: OpenWrt 24.10.1 и новее. Продолжение 0.17 с повторной сверкой Podkop 0.7.22 по официальным исходникам и документации.

## Новое

- Независимое включение/отключение автозапуска без остановки или запуска службы.
- Администраторский просмотр последних 200 строк журнала Atlas, до 32 КиБ.
- Предпросмотр конфигурации без сохранения/применения; секреты и произвольные поля протоколов скрыты.
- Проверка сохранённой конфигурации установленным sing-box без перезапуска.
- Исключения доменов, IP назначения и устройств только из конкретной секции. Трафик затем проверяется следующими правилами. Исключения действуют также на назначенные этой секции списки; отдельный mixed-вход и загрузка списков по-прежнему используют явно выбранный выход.
- Копирование последней сохранённой секции с новым ID. Копия выключена и не открывает HTTP/SOCKS-порт; списки и ручной выбор узла не копируются.
- Объяснение маршрута по сохранённым правилам без сетевого запроса. Учитывает порядок, логические правила и исключения. Неизвестные IP, вход, протокол или бинарный SRS дают неопределённость, а не выдуманный маршрут. Это не проверка фактического соединения или текущего узла selector.
- Поиск доказанных перекрытий первых 1000 простых доменных правил между секциями. Сложные условия и списки не объявляются проверенными этим анализатором.
- Лимит источников списков увеличен с 16 до 64. Общий текстовый кеш остаётся ограничен 50000 записями; файл — 4 МиБ. Лимит секций — 256.

## Сверка

Повторная проверка 2026-10-04 исправила одну завышенную оценку: Podkop check_proxy проверяет существующую конфигурацию sing-box без перезапуска. Эта возможность теперь отмечена общей, а не исключительным преимуществом Atlas. Повторный прогон Windows: 247 тестов, 234 успешны, 13 пропущены; браузерные проверки новых форм также прошли с подменённым RPC. Повторно проверены контрольные суммы, содержимое IPK и совпадение APK внутри архива с отдельным пакетом.

В [таблице](feature-matrix-0.18.md) 70 сценариев: Atlas — 64 реализовано, 6 частично; Podkop — 50 найдены, 20 функций Atlas не найдена в проверенном встроенном наборе. Подтипы протоколов, отдельные поля формы и стратегии одной функции не считаются самостоятельными строками. Это счёт выбранного реестра, а не официальный исчерпывающий каталог приложений.

Частичное покрытие Atlas: точное сопоставление физического входного интерфейса (Atlas использует его IP-подсети), незашифрованные HTTP URL списков, секции без программного лимита, произвольные локальные пути, готовый опубликованный канал/зеркало и отдельная подробная диагностика nftables. Публичное зеркало не развёрнуто.

## Проверки и установка

На Windows: 247 тестов, 234 прошли, 13 платформенных/движковых проверок пропущены. В изолированной Ubuntu: 247 тестов, 237 прошли, 10 пропущены. Отдельные настоящие процессы sing-box 1.12.17/1.14.2 проверяют переключение и секционные исключения; 1.14.2 принял новую схему DNS/FakeIP/списков. Реальный браузер проверяет новые формы с подменённым RPC — это не испытание связи с роутером.

APK 0.18 установлен обновлением с 0.17 на виртуальной OpenWrt 25.12.0 x86_64. sing-box 1.13.21 прошёл проверки маршрута исключённого домена в следующую секцию, выбора выхода списка/загрузки, DNS/FakeIP схемы и изоляции авторизованных прокси-входов. Штатные OpenWrt сценарии пакета могут запускать службу при обновлении; остановка в Atlas выполняется фоновым заданием, результат следует ждать по его статусу.

Для opkg используется luci-app-atlas_0.18.0-1_all.ipk. Для apk — luci-app-atlas-0.18.0-r1.apk, собранный инструментом apk-tools из официального SDK 25.12.0. APK не подписан доверенным ключом, локальная установка требует явного --allow-untrusted. Зависимости устанавливаются из OpenWrt feeds. IPK нельзя подменять APK.

Физический роутер и реальные LAN/WAN ещё не испытаны. Нет сравнительных замеров скорости, RAM/CPU/flash и стабильности с Podkop. Количество функций не доказывает превосходство по этим показателям.

Заключительный прогон установленного APK на OpenWrt 25.12.0 завершился успешно: настоящий ubus RPC проверил предпросмотр и проверку движком без изменения сохранённого состояния и конфигурации, объяснение маршрута с доменными и клиентскими исключениями, выключенную копию секции, автозапуск отдельно от состояния службы, журнал и запуск/остановку через procd/TUN. После отключения автозапуска работающая служба продолжала работать; после включения автозапуска остановленная служба оставалась остановленной. Результат зафиксирован в native-0.18-results.json.
