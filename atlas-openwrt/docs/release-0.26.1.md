# Atlas 0.26.1-r5: проверка совместимости, кэша и памяти

Дата завершения: 7 октября 2026 года. Результат: обнаруженные дефекты исправлены; проверенные сценарии проходят. Универсальная совместимость, отсутствие любых утечек и превосходство над Podkop этими испытаниями не доказаны.

## Исправления

- Устранено накопление отдельных областей Bolt-кэша при каждом запуске расширенной автополитики. Используется одна область, а устаревший выбранный узел отвергается после перезапуска. Публичные идентификаторы Atlas остаются стабильными; FakeIP сохраняется.
- Очистка удалённых списков правил, временных конфигураций проверки секций и записей удалённых профилей. Сохраняются файлы, используемые действующей конфигурацией и откатом. При повреждённой конфигурации очистка пропускается.
- APK-обновление не запускает отключённую службу; новые IPK-хуки не выключают автозапуск при обновлении.
- Экспертные группы с похожими именами не попадают под управление обычной автополитики. Переписываются только ссылки на выходы: пароли и HTTP-заголовки сохраняются.
- В архив попадает только APK текущей ревизии.
- Добавлена явная зависимость python3-logging: без неё concurrent.futures на минимальном OpenWrt мог приводить к последовательной проверке узлов.

Дополнительно до финальной ревизии проверены настоящая цепочка SOCKS→HTTP с передачей данных, отдельные секции и серия из 21 WAN-события: один обработчик и один перезапуск. Эти механизмы в финальной ревизии не менялись. Обновление APK r1→r2 сохраняло настройки и отключённое состояние; финальный r4→r5 пакет также установлен в виртуальной OpenWrt.

## Ограничения и открытые вопросы

- UDP-тест окончательного пакета с постоянной сменой клиентских сокетов доставил 800 запросов, но два потребовали повтора после таймаута (по одному при лимитах 1024 и 65535). Число открытых дескрипторов оставалось 11. Предыдущий тест потребовал четыре повтора. Причина первых таймаутов не установлена; переполнения файловых дескрипторов не обнаружено. Измерения окончательного пакета сохранены в atlas-udp-resources-0261.json.
- Новые домены закономерно увеличивают FakeIP-кэш. Нет абсолютной квоты размера всей базы. Уже накопленные области старой версии автоматически не уплотняются; постоянное изменение конфигурации тоже может оставлять устаревшие записи движка.
- Нет многосуточного испытания на физическом роутере, текущей установки на ARM/MIPS и точной OpenWrt 24.10.1. Проверка Python 3.11 и конфигураций sing-box 1.12.17 полезна, но не заменяет такую установку. Будущие версии OpenWrt/sing-box не гарантированы.
- Большое количество правил, узлов, секций и отсутствие лимита активных соединений требуют ресурсов конкретного роутера. Счётчик функций не доказывает скорость и устойчивость.
- После обновления старых экспертных конфигураций следует заново применить настройки для формирования меток управляемых групп. Старый уже установленный IPK выполняет свой старый хук удаления: миграция с него может отключить автозапуск; новая версия исправляет последующие обновления.

JSON измерений и текстовые журналы приложены рядом с отчётом. Испытания используют локальные контролируемые серверы, без внешнего интернет-трафика. Опубликованная на GitHub версия этим локальным выпуском не обновлена.
