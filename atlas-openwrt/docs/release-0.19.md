# Atlas 0.19 beta — покрытие проверенного набора Podkop

Целевая система: OpenWrt 24.10.1 и новее. Сверка выполнена по официальным исходникам Podkop 0.7.22, по 70 пользовательским сценариям. Полная таблица: feature-matrix-0.19.md и feature-matrix-0.19.json. Покрытие относится к этому реестру, а не к произвольным расширениям sing-box, внешним скриптам или будущим версиям Podkop.

## Изменения

- Фактический входной интерфейс теперь сопоставляется через отдельный TUN с include_interface и правилами iif. Подсети не подменяют интерфейс. Основной TUN исключает эти интерфейсы; общий nft auto-redirect остаётся единственным. Firewall4 получает собственную зону atli+ и разрешение пересылки только в эту зону, удаляемые при остановке. Проверены два разных входа с одинаковыми клиентскими IP, подсетью и UDP-параметрами.
- Списки принимают публичные HTTP и HTTPS URL. Переход с HTTPS на HTTP запрещён; исходный HTTP разрешён. Сохраняются проверки публичного адреса, ограничение размера/времени и прежний рабочий кеш при ошибке. Требования HTTPS к подпискам не ослаблены.
- Удалены ограничения 256 секций и 256 сохранённых выборов selector. Проверено 300 секций. Ограничения памяти, размера RPC, 64 источников списков и 50000 текстовых записей кеша остаются: неограниченные ресурсы не обещаются.
- Собственные абсолютные пути локальных списков, каталога конфигурации и файла кеша. Для собственного пути не требуется отдельная точка монтирования. Символьные ссылки не допускаются; существующие права родительских каталогов сохраняются. Кеш использует файл .db.
- Подробная диагностика nftables в LuCI: таблицы и правила JSON, firewall4, перехват TUN, правила выбора таблиц и маршруты IPv4/IPv6. Только чтение, доступ администратора; отчёт содержит сетевые адреса. Отсутствующие таблицы/маршруты показываются как проблема, а не как успешная проверка.
- Подготовлен публичный канал GitHub Releases в Nissanstels1/Atlas: IPK, APK, архив исходников, контрольные суммы и установщик HTTPS. Тег версии: v0.19.0-beta. Публикация выполняется после испытаний пакетов.
- Исправлен DNS detour к пустому direct outbound: вместо недопустимого обходного выхода используется прямой DNS-запрос. Существующие VPN/direct с дополнительными параметрами сохраняют привязку.

## Проверки

Полный прогон: Windows — 241 успешный тест, 14 пропущены; Linux — 244 успешных, 11 пропущены. Нативный RPC подтвердил запуск/остановку procd, подробную диагностику двух входов и маршрутов, настоящий HTTP-запрос через заданный прокси и загрузку произвольного локального файла. При остановке удаляется собственная зона scoped TUN. Контрольная сумма официального Linux-движка 1.12.17 сверена с метаданными GitHub.

255 тестов backend. Windows без Linux-движка пропускает платформенные проверки. Отдельные браузерные проверки проходят с подменённым RPC; они не заменяют тест службы на роутере. Linux sing-box 1.12.17 принимает схему отдельных входов. На виртуальной OpenWrt 25.12.0 x86_64, sing-box 1.13.21: реальная инъекция UDP через два veth с совпадающей адресацией выбирает выходы A/B независимо. Результаты окончательной установки и RPC фиксируются в native-0.19-results.json.

APK собран официальным apk-tools SDK 25.12.0, архитектура all. Это упаковка приложения; зависимости берутся из OpenWrt feeds. APK не подписан доверенным ключом OpenWrt: установка требует явного --allow-untrusted. Для OpenWrt с opkg нужен IPK, с apk — APK. Стандартные пакетные hooks могут запускать службу при установке/обновлении.

Физический роутер, реальная LAN/WAN и IPv6-трафик между физическими устройствами не испытаны. Нет сравнительных замеров производительности и длительной стабильности. Количество функций и покрытие реестра не доказывают превосходство по скорости, памяти или зрелости.
